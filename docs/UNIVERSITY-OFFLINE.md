# Общий пакет расписаний

После открытия PWA и получения управления service worker приложение с задержкой
3 секунды начинает фоновую загрузку `data/university-schedule.json`.
На старом размещении без общего пакета используется `data/ocr-schedule/bundle.json`.
Загрузка не блокирует первый экран и имеет таймаут 8 секунд. При отказе
следующая попытка возможна после восстановления сети. Пакет не входит в
атомарную установку app shell и не увеличивает обязательный стартовый JS.

Сборщик `scripts/pdf/buildOcrSnapshot.mjs` создаёт пакет из тех же снимков,
что индивидуальные файлы. Контрактный тест сравнивает каждый объект целиком.
Прежний резервный пакет: 633 группы, 2 915 730 байт JSON, 357 964 байта при gzip.
Новый общий пакет объединяет API и резервные снимки. Результат и границы
проверки 01.10 описаны в `UNIVERSITY-DATA-2026-10-01.md`.
Сжатие в сети зависит от хостинга. Расписание остаётся предварительным;
пакет не подтверждает корректность распознавания и не добавляет отсутствующие
в источниках группы.

Service worker сохраняет ответ в runtime-кэш. Если цифровой и индивидуальный
предварительный файлы недоступны, приложение берёт нужную группу из общего
пакета и проверяет её обычным валидатором. Чужая группа под запрошенным ключом,
пустой снимок и неизвестный формат отвергаются. Личный кэш, заметки и события
не очищаются. `/vlsu-api/*` по-прежнему не кэшируется service worker.

## Ограничения

Первый запуск без сети и без ранее сохранённого пакета не может получить
неизвестную группу. Прерванная загрузка, отказ места и очистка кэша браузером
также исключают гарантию общего офлайн-доступа. Сам пакет не заменяет 332
пока отсутствующих источника.
Проверка на физическом iPhone остаётся необходимой.

## Сохранение при обновлении выпуска

Статические JSON-файлы из `data/` сохраняются отдельно от ресурсов интерфейса:
`lad-vlsu-data:<scope>:v1`. Этот кэш не зависит от номера сборки. При активации
SW переносит валидные данные из старого release-кэша и лишь после успешного
переноса удаляет старые ресурсы интерфейса. Кэши других приложений и scope
не затрагиваются. Заметки в IndexedDB и localStorage не меняются.

Для общего пакета и индивидуальных расписаний перед записью проверяются JSON,
schemaVersion, ID группы, непустые занятия, флаг качества и формат хэша.
Пустой пакет, чужой ID и HTML не перезаписывают последний валидный ответ.
Сохранённые данные возвращаются сразу; обновление выполняется в фоне.

312 тестов и сборка прошли. `scripts/qa-data-release-update.cjs` запускает
локальный сервер двух версий: после сохранения пакета воспроизводит старый
release-кэш, запрещает загрузку данных, устанавливает новый SW, закрывает
старую вкладку и повторно открывает приложение. Старый release-кэш удалён,
пакет перенесён. После отключения сети и удаления localStorage-снимка
ЛГ-126 показывает четыре пары. Проверены 402x874 и 430x932, JS-ошибок нет.
Скриншоты: `artifacts/qa/data-release-update/`. Мгновенная смена контроллера
в остающейся открытой вкладке этим сценарием не подтверждена.

## Обновление с открытой заметкой

Новый worker ожидает разрешения приложения перед активацией. Пока открыт
редактор, другое диалоговое окно или поле ввода, текущая вкладка не перезагружается.
После сохранения и закрытия редактора приложение разрешает активацию и применяет
новый выпуск. Обновление, инициированное другой вкладкой, также откладывает
перезагрузку занятого редактора, но согласование всех вкладок отдельно не проверено.

Исправлена незавершённая загрузка фоновых изображений: ответы дочитываются,
запросы ограничены восемью секундами. Непрочитанные потоки удерживали старый worker
и блокировали применение установленного обновления.

## Обновление данных в открытом интерфейсе

Раньше SW записывал новый JSON в кэш, но текущий экран продолжал показывать
старый ответ. Теперь после валидного изменившегося ответа контролируемые вкладки
получают сообщение `static-schedule-updated`. Приложение проверяет отправителя,
scope и выбранную группу. Оно повторно читает уже обновлённый кэш и применяет
данные без reload. Если загрузка ещё выполняется, повторное чтение ставится
в очередь. Память общего пакета сбрасывается, чтобы она не удерживала прежний ответ.

Повторный одинаковый ответ, чужая группа и неправильный scope обновление не
вызывают. Пустые и неверные ответы не заменяют сохранённые расписания.
Сетевое обновление статических JSON ограничено восемью секундами. Позиции
прокрутки сохраняются перед применением данных, в том числе при исчезновении
предупреждения о возрасте снимка.
