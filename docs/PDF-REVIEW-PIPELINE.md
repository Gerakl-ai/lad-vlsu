# Проверка PDF-расписания перед импортом

Файл расписания ИИТЭ за осень 2026 года можно использовать как источник
резервных снимков, пока API ВлГУ отдаёт пустые ответы. Извлечение текста из
PDF не подходит для автоматической публикации: буквы повреждены, а длинные
строки выходят за границы колонок. Этот этап готовит изображения для проверки,
но не создаёт расписание в приложении.

## Официальный архив очной формы

На [странице расписания ВлГУ](https://www.vlsu.ru/studentu/raspisanie-zanjatii/)
размещён ZIP приказа №029/20 от 03.09.2026. В локальной проверке 27.09.2026
его SHA-256 был `52b326d07f68837fb52e9adc4edaea83669c1ca6d1ae9f1513887797b785b091`.
Внутри 11 табличных PDF на 61 странице и один PDF приказа. PDF ИИТЭ в архиве
совпал по SHA-256 с приложенным ранее файлом (`a9cc2c23cfc6f2bfaada9c27349b6d3782157fbbb1bbf0cd2a41dbe0ccd03cd7`).

После загрузки ZIP с официальной страницы локально составить инвентарь:

```powershell
python scripts/pdf/inventory_archive.py --archive "<путь-к-ZIP>" --sha256 52b326d07f68837fb52e9adc4edaea83669c1ca6d1ae9f1513887797b785b091 --out "artifacts/vlsu-sources/order-N029-inventory.json"
```

Скрипт не извлекает файлы и не публикует пары. Он читает названия групп в
таблицах и ищет точное совпадение в сохранённом каталоге `origin/data`.
Последний локальный отчёт: 440 колонок групп, 436 однозначных совпадений,
4 названия отсутствуют в каталоге (`ПЛмк-126`, `ТДк-126`, `Аи-125`, `Аи-123`).
Это потенциальные кандидаты на проверку, **не готовые расписания**. Геометрию,
срок действия и каждую пару нужно сверять отдельно. Названия без совпадения
нельзя привязывать к похожему `nrec` по догадке. ZIP и локальный инвентарь
исключены из Git.

На той же странице есть архивы приказов №028/20 (колледжные подразделения) и
№027/20 (очно-заочная форма). Их проверенные локально SHA-256:

- №028/20: `f4a4470e0adf1176af41c747e9c65b73edb05a65945124fdab7521e05a16de4f`;
- №027/20: `3bea39345b5188e8ad002e50ee22ab4baa9fcbccdfea3ceee33ebd2b0433f2f7`.

Для них используется тот же инвентаризатор с дополнительным `--source-url`
равным ссылке на конкретный ZIP. В №028/20 одна колонка иногда относится сразу
к двум группам; отчёт помечает это `multi-group-column`, а неполное совпадение
`unresolved-multi-group`. Размножать расписание такой колонки на две группы
автоматически нельзя.

После получения трёх локальных отчётов проверить пересечения:

```powershell
python scripts/pdf/summarize_inventories.py "<инвентарь-029.json>" "<инвентарь-028.json>" "<инвентарь-027.json>"
```

Локальная сводка 27.09.2026: 624 колонки, 634 разных группы-кандидата,
7 неразрешённых колонок. `ВиРм-126` встречается и в архиве очной формы, и в
архиве очно-заочной. До сверки с ВлГУ это конфликт источников, а не повод
выбрать один по дате приказа. Публичное покрытие готовыми снимками из-за
инвентаризации **не изменилось**.

## Подсказки для ручной расшифровки

Нужный PDF можно безопасно достать по номеру документа в инвентаре, не
разбирая некорректно закодированные имена файлов внутри ZIP. Например,
документ 8 архива №029/20:

```powershell
python scripts/pdf/extract_pdf_member.py --archive "<путь-к-ZIP>" --inventory "<инвентарь-029.json>" --member 8 --out "artifacts/vlsu-sources/economics-verified.pdf"
```

Проверяются SHA-256 ZIP и внутреннего PDF. Существующий файл с другим
содержимым не заменяется. В `stage_pdf.py` сначала создать crop-изображения
нужной страницы и колонки. Новый manifest сохраняет `pairCount` из подписей
временной шкалы каждого дня: у разных институтов бывает 6 или 7 пар в сетке.
Старый manifest без `pairCount` нужно пересоздать.

Затем получить черновик текстовых блоков:

```powershell
python scripts/pdf/draft_cells.py --source "<проверенный-PDF>" --sha256 "<SHA-256-PDF>" --staging "<manifest.json>" --page 3 --column 5 --out "artifacts/pdf-staging/PI-124.candidates.json"
```

Черновик содержит видимый текст PDF с координатами, предполагаемым номером
пары и предупреждениями. Невидимые служебные номера игнорируются. Выход текста
за колонку, перенос между половинами пары и несколько блоков в одной половине
отмечаются для проверки человеком. На ПИ-124 14 из 31 блоков имеют такие
предупреждения; на выборочной группе института экономики 15 из 22. Даже блок
без предупреждения не считается подтверждённым. Черновик нельзя подать в
`reviewedSnapshot.mjs`: только ревьюер переносит сверенные пары в форму,
а второй человек подтверждает их по изображениям и исходному PDF.

## Подготовить пакет

Нужен Python 3 и PyMuPDF. PDF берётся из [официального архива ВлГУ](https://www.vlsu.ru/studentu/raspisanie-zanjatii/)
или из локальной копии с тем же SHA-256. Сам PDF и изображения не добавляются в
Git. Скрипт не удаляет существующие файлы.

```powershell
python -m pip install pymupdf
python scripts/pdf/stage_pdf.py --source "<путь-к-PDF>" --sha256 a9cc2c23cfc6f2bfaada9c27349b6d3782157fbbb1bbf0cd2a41dbe0ccd03cd7
```

Для проверки одной колонки ПИ-124 на странице 3:

```powershell
python scripts/pdf/stage_pdf.py --source "<путь-к-PDF>" --sha256 a9cc2c23cfc6f2bfaada9c27349b6d3782157fbbb1bbf0cd2a41dbe0ccd03cd7 --page 3 --column 5
```

Пакет находится в `artifacts/pdf-staging/<12 символов SHA>/` и содержит:

- `manifest.json` с хэшем исходника, страницами, колонками и координатами;
- `source-heading.png` для института, курса и срока действия;
- `group-NN/header.png` для названия группы;
- `day-NN.png` для самой колонки;
- `day-NN-context.png` с соседними ячейками на случай выхода текста за границу;
- `time-rail-NN.png` с днём недели и номерами пар.

В `manifest.json` имя группы и `nrec` намеренно оставлены пустыми,
`reviewStatus` равен `needs-review`. Из этого файла приложение ничего не читает.
Даже если текст кажется очевидным, соседний контекст может относиться к другой
группе: ориентиром остаются вертикальные границы основной колонки.

## Что проверить вручную

1. На `source-heading.png` сверить институт, курс и срок действия редакции.
2. Сопоставить название группы из заголовка с `nrec` в каталоге ВлГУ. Не
   угадывать идентификатор по похожему названию.
3. По каждому дню проверить номер пары, время, предмет, тип занятия, аудиторию,
   преподавателя, подгруппу и примечания о неделях. Белые и жёлтые ячейки
   учитывать отдельно: подпись исходного PDF обозначает жёлтые как знаменатель.
4. Проверить объединённые ячейки и текст, выходящий за границы: он может
   относиться к нескольким группам или только к соседней группе.
5. Отдельно сверить номера учебных недель с датами календаря. Снимок нельзя
   показывать после 30.12.2026 как актуальное расписание нового семестра.
6. Для публикации подготовить review-файл с указанием страницы, колонки,
   группы, каждой исходной ячейки и её координат. Второй человек сверяет
   спорные пары. Только после этого формируется снимок схемы v3 с provenance.

Пилот можно начать с нескольких групп ИИТЭ, но покрытие остальных институтов
этот PDF не обеспечивает. Источник, частоту обновлений и право публикации
нужно согласовать с ВлГУ до массового запуска.

## Черновик и проверенный снимок

После сверки колонки с каталогом создаётся пустая форма. Нужен сохранённый
`catalog.json` из ветки `data`; команды ниже не обращаются к API ВлГУ.

```powershell
node scripts/pdf/createReviewTemplate.mjs --staging "artifacts/pdf-staging/a9cc2c23cfc6/manifest.json" --catalog "<путь-к-data/catalog.json>" --nrec 7936a2a43b11b20b01d30f5b00c73166 --page 3 --column 5 --out "artifacts/pdf-staging/a9cc2c23cfc6/PI-124.review.json"
```

Форма создаётся со статусом `draft`. Нужно заполнить:

- `source.title`, официальный HTTPS `source.url`, `validFrom` и `validThrough` в виде `YYYY-MM-DD`;
- `group.pdfHeader` точно по изображению `header.png`, `semester`;
- шесть дней `schedule`: для каждой пары строки `n1`-`n7` и `z1`-`z7`, пустые ячейки оставить пустыми строками;
- для каждой непустой строки один элемент `cells` с `dayIndex`, `mode` (`n` или `z`), `pairIndex`, тем же `rawText`, путём `sourceImage` из manifest и `pageBounds` в координатах PDF;
- после расшифровки `review.status: "approved"` и псевдоним автора в `transcribedBy`.

Важная проверка: жёлтая ячейка означает знаменатель, белая - числитель.
Ограничения вида `(с 9 по 15 нед)` должны остаться в тексте занятия: приложение
уже применяет их к учебному календарю. Объединённую ячейку и каждую подгруппу
нужно сверять по исходной странице, не только по узкому crop.

Второй человек сверяет заполненную форму с PDF, включая день, тип недели,
подгруппы, преподавателя, аудиторию и ограничения по неделям. После сверки
создаёт отдельную форму и заполняет `verifiedBy` своим псевдонимом, а
`verifiedAt` временем проверки в ISO 8601. Имя должно отличаться от
`transcribedBy`. Хэш привязывает подтверждение к точному содержимому формы:
если расшифровку поменяли, старое подтверждение недействительно.

```powershell
node scripts/pdf/createVerificationTemplate.mjs --review "artifacts/pdf-staging/a9cc2c23cfc6/PI-124.review.json" --out "artifacts/pdf-staging/a9cc2c23cfc6/PI-124.verification.json"
node scripts/pdf/reviewedSnapshot.mjs --review "artifacts/pdf-staging/a9cc2c23cfc6/PI-124.review.json" --verification "artifacts/pdf-staging/a9cc2c23cfc6/PI-124.verification.json" --staging "artifacts/pdf-staging/a9cc2c23cfc6/manifest.json" --catalog "<путь-к-data/catalog.json>"
```

Это dry-run. Он сверяет SHA-256 документа, `nrec` и название группы с каталогом,
период, отдельное подтверждение с хэшем, число ячеек, текст ячейки и её координаты.
Успешный dry-run **не является доказательством**, что люди правильно прочитали
PDF или что псевдонимы принадлежат разным людям, и не даёт права публикации.
До согласования с ВлГУ снимок остаётся в
локальном staging. После разрешения и второй сверки к команде можно добавить
`--out "<путь-к-data>" --write`: она создаст новый `schedule/<nrec>.json` и
обновит `coverage.json`, но откажется перезаписать существующую группу.
Публикация ветки `data` остаётся отдельным ручным действием.

У проверенного снимка есть `sourceDocument` и срок действия. Приложение
показывает источник в настройках и не выдаёт пары вне этого периода за
«свободный день». Старые API-снимки без периода продолжают читаться как прежде.

## Проверка скрипта

```powershell
python -m unittest discover -s scripts/pdf -p "test_*.py"
```

На предоставленном 11-страничном PDF скрипт обнаружил 86 колонок групп и по
5 дневных полос на каждой. Все изображения выборочного и полного прогона
сформировались; это проверка геометрии, не точности расписания.
