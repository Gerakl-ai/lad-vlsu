# Данные для университетского пилота ЛАД

Черновик для обсуждения с ИТ-службой ВлГУ. Документ не отправлен и не означает согласия университета на интеграцию или публикацию данных.

## Зачем нужен источник

По состоянию на 02.10.2026 каталог содержит 966 групп. Для 649 групп есть непустые снимки, для 317 нет. В числе отсутствующих 256 заочных, 47 очных и 14 очно-заочных групп. Отчёт `data/gaps.json` содержит поимённый список. Наличие группы в каталоге не гарантирует, что расписание для неё опубликовано.

## Воспроизводимый пример

Официальная [страница расписания](https://www.vlsu.ru/studentu/raspisanie-zanjatii) ведёт на [портал студенческих групп](https://student.vlsu.ru/schedule/institute). На портале без входа доступны форма обучения «Заочная», ИИТЭ и группа ЗИСТд-126 (`Nrec=296ccc855693c856f385c4e4153d1943`). 02.10.2026 портал показывал «Расписание не найдено».

`POST /api/student/GetGroupSchedule` с этим `Nrec`, `WeekDays="1,2,3,4,5,6"` и `WeekType=0`, `1` или `2` отвечал HTTP 200 с пустым телом. Контрольные запросы для ПИ-124 (`Nrec=7936a2a43b11b20b01d30f5b00c73166`) с `WeekType=1` и `2` вернули непустые расписания. Это не позволяет определить, у ЗИСТд-126 действительно нет занятий, данные ещё не внесены или сервис даёт некорректный ответ.

Полный обход 01.10.2026 получил 632 непустых снимка и 334 пустых HTTP 200. Часть пробелов закрыта резервными данными из опубликованных университетом документов, но их содержание требует сверки.

## Что просим уточнить

1. Где хранится утверждённое актуальное расписание для групп, которым публичный API возвращает пустой ответ, прежде всего для заочной формы? Есть ли доступная выгрузка на семестр или сессию?
2. Каков смысл пустого HTTP 200: отсутствие занятий, ещё не опубликованное расписание или ошибка? Можно ли различать эти состояния машинно?
3. Есть ли документированный способ получить по каждой группе период действия, числитель/знаменатель, подгруппу, дату и время пары, аудиторию, преподавателя, отмены и замены? Нужны стабильный идентификатор занятия и время последнего изменения.
4. Какая допустимая частота чтения и механизм обновления предпочтительны: ограниченный API, ETag/delta или периодическая машинно-читаемая выгрузка? Сейчас сборщик запрашивает данные раз в три часа и не перезаписывает валидный снимок пустым ответом.
5. Можно ли открыто публиковать структурированные снимки и ссылки на исходные документы в независимом студенческом приложении? Кто принимает сообщения об ошибках и подтверждает исправления?

## Предлагаемый пилот

Выбрать 10 групп разных институтов и форм обучения, включая ЗИСТд-126 и ПИ-124. Сверить семь дней по первоисточнику предметы, периоды, подгруппы, преподавателей, аудитории и изменения. До такого подтверждения ЛАД остаётся независимым пилотом и не заявляет полное покрытие ВлГУ. Личные записи студентов хранятся только в браузере и не нужны для выгрузки расписания.
