# Данные для пилота расписания ВлГУ

Документ для обсуждения с владельцем расписания и ИТ-службой ВлГУ. Он не
означает, что университет уже согласовал интеграцию или публикацию данных.

## Текущее ограничение

Проверка 28.09.2026: `student/GetGroupSchedule` для ПИ-124 ответил HTTP 200
с пустым телом. Публичная карта покрытия Pages содержала 1 снимок на 965 групп
(`checkedAt`: 27.09.2026). Каталог показывает группы, но не подтверждает наличие
их расписания. Worker хранит отдельные старые ответы, полного архива у него нет.

Официальные PDF-архивы дали 634 названия групп-кандидатов, но распознанный текст
нельзя без сверки превращать в пары. Есть неразрешённые колонки и конфликт форм
обучения. Приложение должно прямо показывать отсутствие данных там, где нет
проверенного источника.

## Что запросить у ВлГУ

1. Ответственного за данные и согласованный способ доступа: исправленный API,
   машиночитаемую выгрузку или иной официальный канал. Для статического PWA
   предпочтительна периодическая выгрузка без запроса к ВлГУ при каждом
   открытии приложения.
2. Полный перечень институтов и групп всех форм обучения со стабильным ID
   (`nrec` либо официальным эквивалентом), статусом группы и периодом действия.
3. Занятия и экзамены: группа, дата или день недели, начало и конец, тип недели,
   диапазон учебных недель, дисциплина, вид занятия, преподаватель, аудитория,
   подгруппа и изменения/отмены. Нужен явный признак «занятий нет», отличный
   от пустого ответа при сбое.
4. Метаданные каждой редакции: `generatedAt`, `validFrom`, `validThrough`,
   идентификатор редакции или хэш, источник, время следующего обновления.
   Уточнить часовой пояс, начало числителя и правило праздничных переносов.
5. Допустимую частоту обращения, лимиты и способ условного обновления (ETag,
   `If-Modified-Since` или дельта). Текущий обход настроен раз в три часа и
   останавливается после трёх пустых ответов из разных институтов.
6. Разрешение на публичное повторное распространение расписаний и изображений
   из PDF, правила использования названия и символики ВлГУ, порядок исправления
   ошибки в опубликованной паре. До согласования официальный PDF остаётся
   источником для локальной сверки, не публикуется как новая база приложения.

## Контракт качества

При выборе группы на GitHub Pages клиент проверяет источники по порядку:
статический снимок Pages, уже сохранённый снимок Worker, затем однократную
загрузку новой группы через Worker с ограничением по времени. Последний шаг
работает только при доступном API ВлГУ; пустой ответ не превращается в
«занятий нет». После успешной загрузки Worker сохраняет проверенный снимок,
который можно открыть позднее без ответа ВлГУ. Локальный кэш устройства
показывается до этих запросов, если группа уже открывалась на этом устройстве.
Это повышает доступность отдельных групп, но не гарантирует расписание всех
групп при текущем публичном покрытии 1/965.

Дополнительно для 597 групп есть навигация к исходной таблице в официальных
ZIP-приказах ВлГУ. Это ссылка и координаты PDF, а не проверенный цифровой
снимок: показатель 597 нельзя прибавлять к охвату машинного расписания 1/965.

- Не заменять последний валидный снимок пустым HTTP 200, ошибкой сети или
  неполной редакцией. Повторная публикация должна быть атомарной.
- Различать три состояния: подтверждённый свободный день, архивный снимок с
  датой и отсутствие расписания. Семестр без срока действия не считать свежим
  бессрочно.
- Сопоставлять расписание с официальным ID группы и формой обучения. Колонку
  PDF, относящуюся к двум группам, не дублировать автоматически.
- Хранить источник и дату получения у каждого снимка, показывать возраст в UI,
  публиковать общий процент покрытия и причины сбоев без личных данных.
- Для PDF требовать построчную сверку и независимое подтверждение точной версии
  расшифровки. Хэш подтверждения защищает от последующей правки, но не
  удостоверяет личность проверяющего.

## Приёмка пилота

1. Выбрать минимум 10 групп разных институтов, курсов и форм обучения, включая
   группы с подгруппами, числителем/знаменателем и экзаменами.
2. Сверить каждую пару с официальным источником и преподавателем/куратором.
   Зафиксировать ошибки и время исправления.
3. Проверить выбор любой группы из каталога, даты, архивный режим, отсутствие
   сети, обновление PWA и переход между Pages и Worker без потери заметок.
4. Перед заявлением «для всех групп» проверить покрытие всего актуального
   каталога: 100% групп должны иметь валидный снимок на нужный семестр либо
   официально подтверждённый статус отсутствия занятий. Текущий 1/965 этому
   критерию не соответствует.

Личные заметки пока хранятся только на устройстве и зависят от origin. Проект
не должен отправлять их в интеграцию с расписанием без отдельного решения
пользователя и проверки требований к персональным данным.
