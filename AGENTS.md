# ЛАД ВлГУ: работа над проектом

## Постоянная цель

Развивать ЛАД как доступное PWA-расписание для всех институтов и групп ВлГУ.
Цель включает достоверные данные, быстрый запуск, сохранность личных записей,
удобный телефонный интерфейс и полноценную компоновку для компьютера.
Указание пользователя от 11.10.2026: продолжать автономное совершенствование
проекта и рабочих методов после каждого завершённого этапа.

Приоритеты и критерии результата: `docs/VLSU-PRODUCT-ROADMAP.md`.
Цикл дальнейшей работы: `docs/CONTINUOUS-IMPROVEMENT.md`.

## Работа с доказательствами

- Сначала сверять рабочую копию, опубликованный релиз и текущую ветку `data`.
- Пустой ответ API означает отсутствие полученных данных. Он не доказывает
  отсутствие занятий и не должен стирать последний пригодный снимок.
- Учебные периоды учитывать отдельно от таблицы предметов и времени пар.
  Не выдавать их добавление за полное покрытие группы.
- Выбирать занятие по предмету конкретного слота и недели. Старый общий номер
  подгруппы не определяет все занятия студента.
- Сохранять происхождение, период действия и качество расписания. Не заполнять
  пробелы выдуманными занятиями или данными соседней группы.
- Личные записи не включать в публичные данные, отчёты и тестовые fixtures.

## Проверка результата

Проверки соразмерять изменению. Для логики данных нужны регрессионные тесты с
реальными контрольными датами. Для интерфейса нужны собранное приложение,
браузерные сценарии, измерения геометрии и просмотр скриншотов.

Команды: `pnpm run check`, `node --check public/sw.js`.
Сценарии: `scripts/qa-desktop-layout.cjs`, `scripts/qa-desktop-surfaces.cjs`,
`scripts/qa-study-periods.cjs`, `scripts/qa-lesson-selection.cjs`,
`scripts/qa-group-header.cjs`, `scripts/qa-group-startup.cjs`,
`scripts/qa-university-cache-race.cjs`.

Для асинхронных условий CacheStorage использовать `waitForAsyncCondition` из
`scripts/qa-async-condition.cjs`. В установленном Playwright 1.63 асинхронный
predicate у `waitForFunction` не подтверждает истинность результата. Перед
офлайн-перезапуском проверять активированный controller и реально записанные файлы.

Состояние реального iPhone не считать проверенным по эмулятору. После публикации
сверять версию HTML и service worker с коммитом и повторять затронутый сценарий
на опубликованном адресе. Публиковать в пределах разрешения пользователя
из текущей переписки.
