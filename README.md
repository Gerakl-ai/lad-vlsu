# Лад ВлГУ

Открытая mobile-first PWA для расписания групп ВлГУ и личных заметок. Это независимый студенческий проект, не официальный сервис университета.

> **Состояние данных на 01.10.2026:** каталог содержит 966 групп. Непустые снимки подготовлены для 649 групп: 632 получены при живом обходе API, остальные сохранены из официальных документов. Для 317 групп данных пока нет. Наличие снимка не подтверждает точность каждой пары, особенно там, где применялось распознавание документа. [Текущее покрытие](https://gerakl-ai.github.io/lad-vlsu/data/coverage.json) доступно в открытых данных проекта.

[Отчёт о пробелах](https://gerakl-ai.github.io/lad-vlsu/data/gaps.json) перечисляет группы без опубликованного расписания по институтам и формам обучения. Он строится заново при каждом выпуске данных; отсутствие снимка не означает, что у группы нет занятий.
[`quality.json`](https://gerakl-ai.github.io/lad-vlsu/data/quality.json) при публикации отдельно считает предварительные, проверенные по документу, остальные доступные и отсутствующие снимки по каждому институту и группе. Категория `otherAvailable` означает только наличие данных, без заявления о ручной проверке.

## Текущий продуктовый этап

- На первом запуске студент находит группу общим поиском по ВлГУ или выбирает институт и группу. Полный каталог сохраняется для повторного поиска без сети.
- Выбранная группа хранится локально; расписания разных групп имеют независимые кэши.
- На том же домене приложение распознаёт старые локальные ключи ПИ-124 без удаления прежнего кэша. Между разными доменами записи автоматически не переносятся.
- На GitHub Pages приложение читает структурно валидные статические снимки из выпуска и ветки `data`. Происхождение унаследованных снимков без метаданных требует отдельной проверки. Cloudflare Worker публикуется отдельно и использует собственные запасные источники данных.
- Старый Worker использует `snapshot:v2`; статические файлы имеют отдельный контракт `schemaVersion: 3`.
- Повреждённый локальный кэш не блокирует запуск, а service worker обновляет HTML и hashed assets как одну версию.
- ПИ-124 остаётся совместимым профилем для существующих пользователей, но больше не зашита в API-адаптер.
- Избранные группы и прямые ссылки ускоряют переключение; предметные заметки изолированы по выбранной группе.
- Непроверенные резервные расписания помечаются в интерфейсе как предварительные, в том числе после запуска из локального кэша. Технический формат источника студенту не показывается.

Расписание читается из статических снимков, собираемых GitHub Actions: [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md).

План превращения персональной версии в открытый мультигрупповой продукт: [docs/VLSU-PRODUCT-ROADMAP.md](docs/VLSU-PRODUCT-ROADMAP.md).

Подготовка университетского показа и безопасная смена названия репозитория: [docs/UNIVERSITY-RELEASE.md](docs/UNIVERSITY-RELEASE.md).

Проверка содержания 633 предварительных расписаний и исправление учебных недель:
[docs/SCHEDULE-CONTENT-AUDIT-2026-10-01.md](docs/SCHEDULE-CONTENT-AUDIT-2026-10-01.md).

## Прозрачность

Обход GitHub Actions публикует изменения в открытой ветке `data`. Там находятся
[`coverage.json`](https://gerakl-ai.github.io/lad-vlsu/data/coverage.json)
и [`status.json`](https://gerakl-ai.github.io/lad-vlsu/data/status.json).
Новый снимок должен иметь проверяемые источник, время и отпечаток. Для
распознанных данных проверка каждой пары ещё продолжается; наличие снимка
не означает, что всё расписание группы подтверждено вручную.

Подробности: [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md).

## Возможности

- расписание из последнего доступного снимка с cache-first запуском и offline reload;
- автоматическое восстановление установленной PWA при несовместимом или устаревшем app shell без удаления записей;
- экраны «Сегодня», «Неделя», «Записи» и «Настройки»;
- девять готовых тем и собственная тема с настройкой фона, текста, акцентов и поверхностей;
- корректное представление одновременных занятий разных подгрупп без склеивания предметов и аудиторий;
- rich-text редактор заметок с заголовками, чек-листами, цветом текста, выделением, цитатами и списками;
- автосохранение черновиков, голосовой ввод и прикрепление масштабируемых фотографий;
- локальная классификация по контексту, пользовательские папки и автоматическая привязка домашних заданий к предметам;
- адаптивная компоновка для портретного и горизонтального положения телефона;
- локальные напоминания, PWA manifest, service worker и резервная копия записей.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется на `http://127.0.0.1:5173/`.

## Проверки

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm cloudflare:check
```

Команда `pnpm check` запускает весь набор. Те же проверки выполняются в GitHub Actions для `main` и pull request.

## GitHub Pages

Основной вариант деплоя. Приложение статическое, а расписание приходит снимками
из ветки `data` — см. [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md). Публикацию
выполняет workflow `.github/workflows/pages.yml`.

Если для выбранной группы нет цифрового снимка, приложение проверяет
`data/ocr-schedule/<nrec>.json`. Такой снимок проходит проверку группы, периода,
хэша исходного документа и структуры ячеек. Студент видит обычное расписание
и дату его обновления; подробности источника доступны в репозитории. Если файла
нет, сохраняется прежняя цепочка:
Worker, затем ВлГУ с ограничением по времени. Личные записи между адресами
не переносятся. Посещённое расписание доступно без сети. Наличие группы в
каталоге не доказывает наличие занятий на текущую дату.
Локальная проверка этой цепочки: собрать приложение с `PAGES_BASE` и
`VITE_SCHEDULE_FALLBACK_URL`, открыть preview с тем же `PAGES_BASE`, затем
запустить `scripts/qa-archive-fallback.cjs` с `QA_URL` и установленным Edge.
Проверка использует тестовый ответ Worker, реальные данные групп не меняет.
Проверка структурированного расписания: `node scripts/qa-ocr-schedule.cjs`.
Проверка открытия без сети: `node scripts/qa-ocr-offline.cjs`.

[Основной адрес](https://germanpolkin.ru/lad-vlsu/) и
[проектный адрес Pages](https://gerakl-ai.github.io/lad-vlsu/)
имеют **разные браузерные хранилища**, хотя показывают один код. Записи и фото
не переезжают между ними автоматически. До удаления старого ярлыка PWA нужно
экспортировать записи на старом адресе и проверить импорт на новом.
Для прежних установок сохранён [старый адрес](https://germanpolkin.ru/vlsu-pi-124-schedule/)
с отдельной копией приложения: оттуда можно экспортировать записи.
Старый и новый пути на `germanpolkin.ru` имеют общий origin и потому используют одно
браузерное хранилище, но разные области service worker и разные версии приложения.
Адрес `workers.dev` и проектный адрес `github.io` имеют отдельные хранилища.
Если записи не видны, сначала проверяйте старую установку и наличие резервной
копии; не удаляйте PWA и не очищайте данные сайта до экспорта.

## Cloudflare Workers

Параллельный вариант деплоя. После переименования репозитория Cloudflare pipeline
нужно проверить отдельно: успешный GitHub Pages deploy не обновляет Worker.
Локальный deploy 01.10.2026 остановился на отсутствии авторизации Wrangler;
dry-run прошёл. Текущую версию Worker нельзя считать равной версии Pages без
проверки. Из-за другого origin его личные записи не появляются на Pages автоматически.

```bash
pnpm build
pnpm deploy
```

`wrangler.jsonc` публикует `dist`, направляет `/vlsu-api/*` и `/app-api/*` через `src/worker.ts`, а также подключает binding `CF_VERSION_METADATA`. Версия Wrangler зафиксирована в `package.json`, поэтому локальный и Git-деплой используют один инструмент.

Для Cloudflare Workers Builds с GitHub:

```text
Production branch: main
Build command: pnpm build
Deploy command: pnpm exec wrangler deploy
```

Если Cloudflare Workers Builds подключён к этому репозиторию, push в `main` может запускать отдельную сборку. Её результат нельзя выводить из статуса GitHub Pages: активную ревизию Worker нужно проверить запросом `GET /app-api/health` и сопоставить с развёрнутой версией приложения.

## Cloudflare Pages

Pages остаётся совместимым вариантом для расписания:

```text
Build command: pnpm build
Build output directory: dist
```

`functions/vlsu-api/[[path]].ts` проксирует API ВлГУ для прежних развёртываний. Разбор записей выполняется на устройстве и внешних сервисов не требует.

## Уведомления

Локальное напоминание работает, пока браузер может выполнить запланированный код. Для гарантированной доставки при полностью закрытом приложении нужен Web Push: установленная на экран «Домой» PWA, push subscription и серверный отправитель. Service worker уже умеет принимать push-события, но серверная регистрация подписок в эту локальную версию не входит.

## Данные и приватность

Расписание кэшируется локально. Записи, пользовательские папки, черновики и вложенные изображения хранятся в IndexedDB текущего устройства и origin. Классификация записей выполняется целиком в браузере: внешних сервисов и облачной обработки текста нет. Резервная копия записей доступна в настройках; успешное нажатие «Экспорт» не заменяет проверки скачанного файла и пробного импорта.
