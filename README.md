# Лад ВлГУ

Открытая mobile-first PWA для расписания групп ВлГУ и личных заметок. Это независимый студенческий проект, не официальный сервис университета.

> **Состояние данных на 24.09.2026:** каталог содержит 965 групп, но публичный валидный снимок расписания есть только для ПИ-124 (1/965). API расписания ВлГУ возвращает пустой HTTP 200; автоматический обход сохраняет прежние данные и не выдаёт сбой за день без пар. Наличие группы в поиске не означает доступность её расписания. [Покрытие и время снимков](https://gerakl-ai.github.io/vlsu-pi-124-schedule/data/coverage.json) обновляются отдельно от приложения.

## Текущий продуктовый этап

- На первом запуске студент выбирает институт и группу из публичного каталога ВлГУ.
- Выбранная группа хранится локально; расписания разных групп имеют независимые кэши.
- Старые установки ПИ-124 автоматически мигрируют на новую схему без удаления прежнего кэша.
- На GitHub Pages приложение читает структурно валидные статические снимки из ветки `data`; происхождение унаследованного снимка ПИ-124 ещё требует проверки. Cloudflare Worker публикуется отдельно и использует собственные запасные источники данных.
- Старый Worker использует `snapshot:v2`; статические файлы имеют отдельный контракт `schemaVersion: 3`.
- Повреждённый локальный кэш не блокирует запуск, а service worker обновляет HTML и hashed assets как одну версию.
- ПИ-124 остаётся совместимым профилем для существующих пользователей, но больше не зашита в API-адаптер.
- Избранные группы и прямые ссылки ускоряют переключение; предметные заметки изолированы по выбранной группе.

Расписание читается из статических снимков, собираемых GitHub Actions: [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md).

План превращения персональной версии в открытый мультигрупповой продукт: [docs/VLSU-PRODUCT-ROADMAP.md](docs/VLSU-PRODUCT-ROADMAP.md).

## Прозрачность

Обход GitHub Actions публикует изменения в открытой ветке `data`. Там находятся
[`coverage.json`](https://gerakl-ai.github.io/vlsu-pi-124-schedule/data/coverage.json)
и [`status.json`](https://gerakl-ai.github.io/vlsu-pi-124-schedule/data/status.json).
Новый снимок должен иметь проверяемые источник, время и отпечаток. Единственный
унаследованный снимок ПИ-124 пока **не имеет подтверждённого provenance**;
его нельзя представлять как свежую проверенную выгрузку ВлГУ.

Подробности: [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md).

## Возможности

- расписание из последнего доступного снимка с cache-first запуском и offline reload;
- автоматическое восстановление установленной PWA при несовместимом или устаревшем app shell без удаления записей;
- экраны «Сегодня», «Неделя», «Записи» и «Настройки»;
- девять готовых тем и собственная тема с настройкой фона, текста, акцентов и поверхностей;
- корректное представление одновременных занятий разных подгрупп без склеивания предметов и аудиторий;
- rich-text редактор заметок с заголовками, чек-листами, цветом текста, выделением, цитатами и списками;
- автосохранение черновиков, голосовой ввод и прикрепление масштабируемых фотографий;
- локальная классификация по контексту, пользовательские папки и автоматическая привязка домашних заданий к предметам;
- адаптивная компоновка для портретного и горизонтального положения телефона;
- локальные напоминания, PWA manifest, service worker и резервная копия записей.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется на `http://127.0.0.1:5173/`.

## Проверки

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm cloudflare:check
```

Команда `pnpm check` запускает весь набор. Те же проверки выполняются в GitHub Actions для `main` и pull request.

## GitHub Pages

Основной вариант деплоя. Приложение статическое, а расписание приходит снимками
из ветки `data` — см. [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md). Публикацию
выполняет workflow `.github/workflows/pages.yml`.

Если для выбранной группы нет статического снимка, Pages быстро проверяет
сохранённый снимок на Worker. Запрос не обращается к ВлГУ и не переносит личные
записи между адресами. Если Worker раньше не сохранил эту группу, расписание
останется недоступным: наличие группы в каталоге не означает наличие её пар.
Возраст резервного снимка показывается в приложении. Покрытие всех групп требует
надёжной выгрузки ВлГУ или проверенного импорта официальных документов.
Локальная проверка этой цепочки: собрать приложение с `PAGES_BASE` и
`VITE_SCHEDULE_FALLBACK_URL`, открыть preview с тем же `PAGES_BASE`, затем
запустить `scripts/qa-archive-fallback.cjs` с `QA_URL` и установленным Edge.
Проверка использует тестовый ответ Worker, реальные данные групп не меняет.

[Основной адрес](https://germanpolkin.ru/vlsu-pi-124-schedule/) и
[проектный адрес Pages](https://gerakl-ai.github.io/vlsu-pi-124-schedule/)
имеют **разные браузерные хранилища**, хотя показывают один код. Записи и фото
не переезжают между ними автоматически. До удаления старого ярлыка PWA нужно
экспортировать записи на старом адресе и проверить импорт на новом.

## Cloudflare Workers

Параллельный вариант деплоя. Проверка 24.09.2026 показала новое развёртывание
Worker после push в GitHub; это отдельный Cloudflare pipeline, **не** результат
workflow GitHub Pages. Его версия и доступность должны проверяться отдельно. Из-за другого origin
его личные записи также не появляются на Pages автоматически.

```bash
pnpm build
pnpm deploy
```

`wrangler.jsonc` публикует `dist`, направляет `/vlsu-api/*` и `/app-api/*` через `src/worker.ts`, а также подключает binding `CF_VERSION_METADATA`. Версия Wrangler зафиксирована в `package.json`, поэтому локальный и Git-деплой используют один инструмент.

Для Cloudflare Workers Builds с GitHub:

```text
Production branch: main
Build command: pnpm build
Deploy command: pnpm exec wrangler deploy
```

Если Cloudflare Workers Builds подключён к этому репозиторию, push в `main` может запускать отдельную сборку. Её результат нельзя выводить из статуса GitHub Pages: активную ревизию Worker нужно проверить запросом `GET /app-api/health` и сопоставить с развёрнутой версией приложения.

## Cloudflare Pages

Pages остаётся совместимым вариантом для расписания:

```text
Build command: pnpm build
Build output directory: dist
```

`functions/vlsu-api/[[path]].ts` проксирует API ВлГУ для прежних развёртываний. Разбор записей выполняется на устройстве и внешних сервисов не требует.

## Уведомления

Локальное напоминание работает, пока браузер может выполнить запланированный код. Для гарантированной доставки при полностью закрытом приложении нужен Web Push: установленная на экран «Домой» PWA, push subscription и серверный отправитель. Service worker уже умеет принимать push-события, но серверная регистрация подписок в эту локальную версию не входит.

## Данные и приватность

Расписание кэшируется локально. Записи, пользовательские папки, черновики и вложенные изображения хранятся в IndexedDB текущего устройства и origin. Классификация записей выполняется целиком в браузере: внешних сервисов и облачной обработки текста нет. Резервная копия записей доступна в настройках; успешное нажатие «Экспорт» не заменяет проверки скачанного файла и пробного импорта.
